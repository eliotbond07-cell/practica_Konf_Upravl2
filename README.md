# Инструмент визуализации графа зависимостей для менеджера пакетов
## Этап 1. Минимальный прототип с конфигурацией
Цель: создать минимальное CLI-приложение и сделать его настраиваемым.

Прототип поддерживает конфигурационный файл формата TOML.
Имеются настраиваемые параметры:
* Имя анализируемого пакета.
* URL-адрес репозитория или путь к файлу тестового репозитория.
* Режим работы с тестовым репозиторием.
* Имя сгенерированного файла с изображением графа.
* Режим вывода зависимостей в формате ASCII-дерева.

При запуске прототипа выводятся все параметры в формате ключ-значение или 
описание ошибки при загрузке конфигурации.

## Этап 2. Сбор данных
Цель: реализовать основную логику получения данных о зависимостях для их 
дальнейшего анализа и визуализации. Запрещено пользоваться менеджерами 
пакетов и сторонними библиотеками для получения информации о зависимостях 
пакетов.

* Используется формат пакетов Alpine Linux (apk).
* Информация о прямых зависимостях заданного пакета извлекается, через
URL-адрес репозитория.

При запуске выводятся все прямые зависимости или описание ошибки 
при загрузке конфигурации или информации о зависимостях пакетов.

## Этап 3. Основные операции
Цель: построить граф зависимостей (с учетом транзитивности) и выполнить 
основные операции над ним.

* Получение графа зависимостей реализовано алгоритмом BFS без рекурсии.
* Случаи наличия циклических зависимостей обрабатываются корректно, 
такие зависимости выводятся отдельно.
* Поддерживается режим тестирования.
* Вместо URL реального репозитория, имеется возможность указать путь
к файлу описания графа репозитория, где пакеты называются большими 
латинскими буквами.

При запуске выводится порядок обхода графа зависимостей, а также указывается 
наличие циклических зависимостей. Если такие имеются, они выводятся на экран.

## Этап 4. Дополнительные операции 
Цель: выполнить дополнительные операции над графом зависимостей. 

* Поддерживается режим вывода порядка загрузки зависимостей для заданного пакета, 
с помощью топологической сортировки Кана.
* Результаты вывода можно сравнить с реальным менеджером пакетов apk. Имеются 
некритичные расхождения между результатами из-за различий в методе сортировки.

При запуске выводится порядок обхода графа зависимостей, а также указывается 
наличие циклических зависимостей. Если такие имеются, они выводятся на экран.
Далее выводится порядок загрузки зависимостей.

## Этап 5. Визуализация 
Цель: получить графическое представление графа зависимостей.

* Формируется текстовое представление графа зависимостей на языке диаграмм Graphviz.
* Изображение графа сохраняется в файле формата .png.
* При задании соответствующего параметра конфигурации, зависимости выводятся в виде 
ASCII-дерева.
* Результаты вывода можно сравнить с реальным менеджером пакетов apk. Имеются 
некритичные расхождения между результатами из-за различий в методе сортировки, 
а также из-за того, что не учитываются зависимости, которые начинаются на "so:".

При запуске выводится порядок обхода графа зависимостей. По этому графу формируется 
текстовое представление на языке Graphviz и сохраняется изображение в формате PNG. 
При соответствующем параметре выводится граф в виде ASCII-дерева.
